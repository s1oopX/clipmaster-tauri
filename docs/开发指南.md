# ClipMaster 开发指南

## 📋 标准开发流程

### 1️⃣ 开始新功能/修复

```powershell
# 1. 确保在最新代码上工作
git pull origin master

# 2. (可选) 创建新分支
git checkout -b feature/新功能名称

# 3. 启动开发服务器
npm run tauri:dev
```

### 2️⃣ 开发过程中的验证

**每次修改前端代码后**：
- 开发服务器会自动热重载，观察浏览器是否正常显示
- 检查控制台是否有报错

**每次修改后端 Rust 代码后**：
- 开发服务器会自动重新编译 Rust
- 应用会自动重启
- 观察终端输出是否有编译错误

### 3️⃣ 提交前的完整验证

```powershell
# 步骤 1: 运行前端测试
npm test

# 步骤 2: 检查 Rust 代码格式
cd src-tauri
cargo fmt --check
cargo clippy  # 可选但推荐

# 步骤 3: 类型检查和构建验证
cd ..
npm run build

# 步骤 4: (可选) 完整打包测试
npm run tauri:build
```

### 4️⃣ 手动冒烟测试清单

运行 `npm run tauri:dev` 后，逐项验证：

- [ ] 启动应用，界面正常显示
- [ ] 复制一段文本，列表出现新记录
- [ ] 再复制同样内容，确认不会重复出现
- [ ] 截图或复制图片，确认显示正常
- [ ] 点击搜索，输入关键词，结果正确
- [ ] 点击收藏/置顶，UI 状态更新
- [ ] 点击删除，记录消失
- [ ] 点击复制按钮，文本写回剪贴板
- [ ] 关闭应用重新打开，历史记录还在

### 5️⃣ 提交代码

```powershell
# 1. 查看修改
git status
git diff

# 2. 添加文件（避免添加构建产物）
git add src/ src-tauri/src/ docs/ package.json

# 3. 提交（我会自动推送）
git commit -m "feat: 添加新功能描述"
# 或
git commit -m "fix: 修复某个 bug"
```

### 6️⃣ 发布版本

```powershell
# 1. 更新版本号
# 编辑 package.json 和 src-tauri/Cargo.toml 中的 version

# 2. 完整构建
npm run tauri:build

# 3. 测试安装包
# 运行 src-tauri/target/release/bundle/nsis/ClipMaster_x.x.x_x64-setup.exe

# 4. 打标签
git tag v0.2.0
git push origin v0.2.0
```

## 🛠️ 常见问题

### 开发服务器启动失败
```powershell
# 清理缓存重新安装
rm -rf node_modules package-lock.json
npm install
```

### Rust 编译错误
```powershell
# 清理 Rust 构建缓存
cd src-tauri
cargo clean
cargo build
```

### 热重载不工作
- 检查 Vite 端口 5174 是否被占用
- 重启开发服务器

### 图片不显示
- 检查 `convertImagePath` 的路径转换
- 确认 `%APPDATA%/com.clipmaster.app/images/` 存在

## 💡 开发建议

1. **小步提交**：每完成一个小功能就提交，不要积累太多改动
2. **测试先行**：修改功能前先写测试用例
3. **文档同步**：新增 API 要同步更新 `docs/API.md`
4. **代码审查**：提交前 self-review 一遍 diff
5. **保持整洁**：定期运行 `cargo clean` 清理构建缓存
